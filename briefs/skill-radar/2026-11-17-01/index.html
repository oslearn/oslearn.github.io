Skill 雷达｜2026年11月17日（第1期）

发表于 2026-11-18 11:14 更新于 2026-11-19 10:55 分类于 Skill 雷达

本期围绕编码、研究、自动化，介绍值得关注的 Skill，重点说明功能、应用场景与使用限制。

Skill 概览

下表展示本期候选，收录不等于推荐；详细介绍见后文。

Skill 功能简介 主要应用场景
design-mobile-apps 通过Sleek设计服务迭代移动应用界面，并衔接原型与代码实现。 移动应用界面原型迭代；设计到前端实现的交接
agent-browser 用浏览器无障碍树和元素引用，组织网页观察、定位与交互操作。 已授权网页的重复流程操作；前端功能与页面交互检查
write-work-summary 将真实工程证据和成果整理为按影响排序的工作总结。 工程贡献回顾与总结；已有成果材料的整理汇报
rea-ci-tests-audit 追踪工作流和测试入口，审查回归捕获、假通过与性能成本。 CI假绿和测试盲区排查；测试加速方案的等价工作量审查
webapp-testing 用Python Playwright组织本地网页交互测试和日志查看。 前后端联调后的回归检查；页面交互与控制台异常定位
python-error-coach 依据代码和报错给出Python最小修复，并用练习帮助理解错误。 Python基础报错诊断；编程教学与理解检查
webmcp-gen 将网页真实流程组织成实验性WebMCP工具，并校验可见页面效果。 网页语义工具研究；重复UI流程的工具化设计
write-talent-card 依据既定评级和真实工程证据整理人员校准材料，不自行评级。 人员校准材料整理；既定评级依据的事实归纳
reverse-engineer-anything 为授权软件制品、既有捕获和运行目标选择REA证据分析路径。 授权软件制品核对；既有捕获解释与版本对比
vercel 在既有授权下检查Vercel受保护预览及不同特性开关版本。 Vercel受保护预览验证；不同环境和版本的浏览差异核对
write-promo-doc 用真实成果和目标职级要求组织晋升材料，并保留反对理由与缺口。 已有晋升材料组织；工程成果与职级要求对照
reverse-engineer-anything 同一REA技能的另一客户端入口，功能与已保留条目一致。 同一制品分析流程的另一入口

本期推荐

1. design-mobile-apps

把移动应用的设计需求送入 Sleek，按创建项目、异步设计、查看组件和截图的流程迭代，再按另一份实现指南转成 React Native 或 HTML。它是设计服务的操作技能，不是本地独立设计引擎。

适用场景

  • 移动应用界面原型迭代
  • 设计到前端实现的交接

可以这样提出任务（示意）

为一个移动阅读应用整理页面和交互需求，先说明Sleek账号、费用及数据使用范围，再提出原型迭代方案。

使用前提与限制：需要Sleek账号、API授权及实现环境；持续使用涉及费用，价格与额度未重新核验，需求和参考图可能外发；原采集未完整审阅实现指南。

2. webmcp-gen

为已有网页的真实流程生成实验性WebMCP工具，并保存manifest、初始化脚本、评测配置和报告。它要求验证工具注册、参数、可见页面效果、错误恢复与取消，而不只验证返回JSON。

适用场景

  • 网页语义工具研究
  • 重复UI流程的工具化设计

可以这样提出任务（示意）

梳理已授权网页流程的工具参数和可见结果，提出注册、错误恢复与取消验证方案；缺少对照环境时保留比较未完成状态。

使用前提与限制：需要agent-browser、已授权目标及支持实验特性的环境；网页模式和返回值是不可信输入，JSON Schema及只读提示不构成授权；原采集未验证实现和浏览器兼容性。

3. agent-browser

面向Agent的浏览器自动化入口，使用Chrome/Chromium的CDP与无障碍树元素引用，把页面观察、定位和操作接起来。当前SKILL.md是发现入口，真正操作指南由已安装CLI按版本提供。

适用场景

  • 已授权网页的重复流程操作
  • 前端功能与页面交互检查

可以这样提出任务（示意）

在已授权网站中检查指定操作流程，先说明会话范围并记录每一步结果；涉及提交表单或发送内容时确认授权。

使用前提与限制：需要对应CLI、浏览器环境和与安装版本一致的core指南；登录状态与截图可能敏感，外部写入须授权；原材料仅含入口说明，不保证全部专题能力兼容。

4. rea-ci-tests-audit

审查REA的CI与测试是否真正捕获回归，追踪工作流到实际执行入口，检查夹具漂移、假通过和性能成本。它强调固定基线、控制故障与等价工作量，不为变绿而削弱验证。

适用场景

  • CI假绿和测试盲区排查
  • 测试加速方案的等价工作量审查

可以这样提出任务（示意）

审查这个项目的CI绿灯是否对应真实测试执行，列出工作流、入口及产物证据；只提出隔离验证方案，不修改生产流程。

使用前提与限制：需要固定基线、工作流、测试与运行证据，REA专用规则迁移时需适配；受控故障仅在隔离副本验证，调查不授权提交、推送或合并。

5. reverse-engineer-anything

把授权的软件制品、打包应用、已有网络捕获和明确运行目标路由到REA的相应分析工具，并以证据ID、来源哈希和已知限制组织后续查询。普通完整源码阅读不要求使用它。

适用场景

  • 授权软件制品核对
  • 既有捕获解释与版本对比

可以这样提出任务（示意）

基于已授权的软件制品和既有捕获整理分析路线，先说明REA工具、目标边界和未知项；未获单独授权时不运行、附加或新建捕获。

使用前提与限制：需要另行可用的REA CLI或MCP及相应工具依赖；运行、附加和捕获的授权不同，原恢复指南仅为截断片段，未审阅全部格式指南，不能认定完整工具链已验证。

6. webapp-testing

用Python Playwright测试本地Web应用，按静态或动态页面、服务器是否已启动选择路径，先查看渲染页面再操作，并通过辅助脚本管理一个或多个本地服务。

适用场景

  • 前后端联调后的回归检查
  • 页面交互与控制台异常定位

可以这样提出任务（示意）

检查已运行的本地应用中表单和按钮的行为，记录失败步骤、截图和控制台日志，并说明未覆盖的测试范围。

使用前提与限制：需要Python、Playwright、浏览器及可运行的本地服务；默认端口和等待策略须按项目调整，原采集未核查许可全文或服务器管理脚本。
