Skill 雷达｜2026年11月19日

发表于 2026-11-19 16:05 更新于 2026-11-19 16:05 分类于 Skill 雷达

本期围绕编码、研究、自动化，介绍值得关注的 Skill，重点说明功能、应用场景与使用限制。

Skill 概览

下表展示本期候选，收录不等于推荐；详细介绍见后文。

Skill 功能简介 主要应用场景
grill-me 把计划或设计交给 grilling 技能，通过访谈进一步澄清思路。 技术方案讨论前梳理想法；产品计划的问答式推敲
frontend-design 先确定配色、字体与布局，再实现并自查贴合产品主题的前端页面。 产品落地页的视觉设计；内容网站和现有界面的改版
grill-with-docs 组合调用访谈与领域建模技能，目标是让方案讨论同步形成文档。 技术决策讨论的文档沉淀；团队术语和概念的统一
improve-codebase-architecture 扫描代码库的架构摩擦，用改造前后图示辅助选择重构方向。 老项目的重构机会评估；频繁改动模块的可测试性讨论
research 让后台代理查阅一方资料，并在项目中形成逐项带引用的研究笔记。 实现功能前核对 API 和协议；技术选型的资料整理
webapp-testing 用 Python Playwright 操作本地网页，采集截图与日志并检查交互。 本地网页的表单按钮检查；前后端联调后的日志排查
twitter-automation 通过 belt CLI 调用 X 发帖、读帖、私信和关注等社交操作。 已有授权的 X 内容发布集成；图文或视频生成后的发帖衔接
lark-workflow-standup-report 合并飞书日程和未完成待办，生成开工摘要及会议冲突提醒。 每天开工前查看安排；站会前整理个人日程待办
kakaotalk 用 macOS 辅助功能和本地 OCR 读取 KakaoTalk 消息，并支持授权后的发送预约。 Mac 版 KakaoTalk 的个人消息整理；明确授权的消息发送预约
rea-ci-tests-audit 检查 REA 的 CI 假通过、夹具漂移及性能优化是否保留真实回归检测。 REA 工程的 CI 假通过调查；测试加速方案的证据审核
notion-research-documentation 检索多个 Notion 页面，将资料整理为带来源引用的简报或对比报告。 把项目资料整理为研究简报；比较散落于多个页面的方案
python-debugpy 按故障位置选择 pdb 或 debugpy，检查 Python 栈帧、变量与异常现场。 Python 异常和状态变化排查；无界面服务的受控远程调试

本期推荐

1. twitter-automation

将 X 的发帖、读帖、点赞、转发、私信和关注等操作组织成 belt CLI 的调用示例，也给出生成图片或视频后再发帖的串联方式。适合已有账号授权的内容运营集成，入口没有给出可直接使用的定时调度器。

适用场景

  • 已有授权的 X 内容发布集成
  • 图文或视频生成后的发帖衔接

可以这样提出任务（示意）

为这篇公开文章准备 X 发布内容并检查集成所需参数；先输出草稿和授权检查结果，不执行发帖或私信。

使用前提与限制：需要 belt CLI、第三方服务登录和 X 授权；会外发内容并可能产生费用，真实账号写入须明确授权。入口未提供可靠定时调度实现。

2. notion-research-documentation

从多个 Notion 页面检索和读取资料，按研究主题归纳事实、差异与证据缺口，再选择简报、比较或长报告格式。流程包含创建或更新 Notion 文档，并保留来源链接与引用，方便后续核查和补充。

适用场景

  • 把项目资料整理为研究简报
  • 比较散落于多个页面的方案

可以这样提出任务（示意）

查阅我授权范围内的 Notion 项目材料，整理一份带来源链接的方案对比；先给出草稿，确认写入范围后再保存页面。

使用前提与限制：需要已授权的 Notion MCP 和可访问页面；读取资料涉及隐私，创建或更新文档须明确写入范围。配套模板及工具兼容性需另行核对。

3. lark-workflow-standup-report

把飞书日程与未完成任务读取结果合并为开工摘要，按时间排列会议和待办，标明到期情况，并给出冲突提醒与空闲时段。重点是显式过滤已完成任务，避免把已处理事项再次列入待办。

适用场景

  • 每天开工前查看安排
  • 站会前整理个人日程待办

可以这样提出任务（示意）

整理我指定日期的飞书日程和未完成任务，按时间排序并提示冲突；只生成个人摘要，不发送到群聊。

使用前提与限制：需要 lark-cli、用户身份及日历任务读取授权。数据可能敏感；默认任务分页和复杂日程交叠需核对，认证规则须阅读配套共享技能。

4. python-debugpy

按调试目标选择 Python 内置断点、pdb 或 debugpy：本地脚本可单步检查状态，异常后可进入故障现场，远程或无界面进程可使用调试协议连接。流程还提醒确认目标进程、控制监听地址，并在结束后清理调试代码和重跑普通测试。

适用场景

  • Python 异常和状态变化排查
  • 无界面服务的受控远程调试

可以这样提出任务（示意）

为这个 Python 异常设计最小复现和调试步骤，先检查故障栈帧；不要附加生产进程或暴露调试端口。

使用前提与限制：需要 Python，远程调试还需 debugpy 和兼容客户端；端口限本机或受保护隧道，进程附加和暂停须授权，结束后清理断点并重跑测试。

常青回顾

5. improve-codebase-architecture

从近期改动频繁或用户指定的代码区域寻找架构摩擦，识别接口复杂、理解成本分散的模块，并生成带改造前后图示的 HTML 评审报告。选定方向后，再通过问答明确约束，按需更新术语和决策记录。

适用场景

  • 老项目的重构机会评估
  • 频繁改动模块的可测试性讨论

可以这样提出任务（示意）

查看最近经常修改的代码，找出值得重构的模块，生成改造前后图示报告；先讨论建议，不直接修改实现。

使用前提与限制：需要代码库、提交历史及配套设计和访谈技能；报告使用外部 CDN，敏感结构不要公开。后续文档写入和重构须明确授权。

6. frontend-design

帮助助手先确定产品主题、受众与视觉方向，再建立配色、字体和布局方案，审核后实现页面，并持续自我检查。重点是让设计选择服务于真实内容，而不是把所有页面套进相同卡片模板。

适用场景

  • 产品落地页的视觉设计
  • 内容网站和现有界面的改版

可以这样提出任务（示意）

为这款面向独立开发者的工具设计落地页，先说明视觉方案，再实现页面并检查手机端和键盘操作。

使用前提与限制：需要前端项目环境和清晰的产品简报；字体、图片及技能许可需另行核对，设计建议不替代响应式和可访问性验收。
