README 功能整理

1. elementalsouls/Claude-BugHunter

核心定位：项目方把面向外部安全评估的资料和工作流打包成代理技能，其中含范围核对、发现分诊、报告写作与证据处理。

主要功能：

  • 根据评估主题载入相关说明，提供分诊和报告模板。
  • 在提交发现前提示核对授权范围、接收方接受的影响类型与证据质量。

适用场景：

  • 为已经掌握的自有资产安全发现整理修复工单与去标识化证据。
  • 评审安全团队的发现分诊和报告流程。

使用前提：需要支持该技能包的代理宿主，例如 README 列出的 Claude Code；实际资产评估仍需资产归属或明确书面授权。

权限与限制：项目也含外部红队资料；本期仅介绍防御性分诊和报告，不提供攻击操作。工具内的范围检查不等于授权，不宜交由代理自行决定目标或提交发现。

许可证提示：该版本 README 区分代码的 MIT 与方法文档等内容的 CC BY 4.0，不能用仓库的 MIT 标签概括全部文件。

来源：README（本期参考版本）

2. obra/superpowers

核心定位：一套编码代理技能，先确认需求和设计，再拆成可验证的实施步骤，并把测试、评审与结束分支纳入同一流程。

主要功能：

  • 在开工前用问题澄清需求，请用户确认设计，再生成含文件位置和验证步骤的计划。
  • 支持独立工作树、先写失败测试再实现，以及实现后的复核；可分派子任务，也可在当前会话执行。

适用场景：

  • 把跨模块需求拆成能单独测试和评审的小改动。
  • 修复难以复现的问题时，先记录根因证据，再用测试确认修复。

使用前提：需受支持的编码代理宿主，按宿主分别安装；用到工作树和测试时，还需要可用的 Git 与项目测试环境。

权限与限制：自动触发不保证每个代理都遵守流程；需审阅测试与提交结果。可选的可视化组件默认会访问项目方网站获取带版本信息的标志。

许可证提示：固定版本 README 标明 MIT；仓库源码许可不代表另列的商业服务免费。

来源：README（本期参考版本）

3. XiaoYouChR/Ghost-Downloader-3

核心定位：跨平台下载管理器，将常见文件和媒体协议的传输任务放在同一个工具里管理，另提供命令行和浏览器扩展。

主要功能：

  • README 列出 HTTP、FTP、Magnet/BT 和 HLS 等来源，并支持下载任务的暂停和恢复。
  • 命令行可先预览地址而不创建任务，也能查询任务状态；浏览器扩展可将下载交给桌面端。

适用场景：

  • 将获准获取的公开数据文件和媒体素材交给统一的下载队列。
  • 在脚本中查询和等待既有下载任务，不必打开桌面界面轮询。

使用前提：固定版本 README 列出 Windows、macOS、Linux 和 Android 的系统与架构要求；桌面版还需留意 Qt 对旧 CPU 的限制。

权限与限制：浏览器扩展可能把认证状态交给桌面端，需审核扩展权限；仅下载有权获取的文件，不把 README 的速度描述当实测结果。

许可证提示：固定版本 README 标明 GPL v3.0；下载内容自身的权利与程序许可是两回事。

来源：README（本期参考版本）

4. firecrawl/firecrawl

核心定位：为检索和代理工作流提供网页正文与 URL 列表，同一项目区分本地程序、托管服务和完整服务器自部署。

主要功能：

  • 将页面正文转换为 Markdown，也能列举站点 URL 或批量采集多页。
  • 本地端可提供兼容接口；托管端额外提供结构化输出和 Alexandria 等数据能力。

适用场景：

  • 把获准采集的产品文档整理成可检索的 Markdown 语料。
  • 先生成站点页面清单，再挑出帮助页批量归档。

使用前提：README 的本地构建路径需要 Rust 和 C 编译器；完整自部署示例还涉及 Docker Compose、Redis、PostgreSQL 和浏览器服务。

权限与限制：本地版某些单页抓取默认可能回退到云端；敏感网址或内容须先检查数据流和云端开关。使用前核对网站条款、隐私和 robots 规则。

许可证提示：README 称主体采用 AGPL-3.0，SDK 和部分界面组件为 MIT，具体应按组件核对。

来源：README（本期参考版本）

5. cathrynlavery/diagram-design

核心定位：面向文档和文章配图的代理技能，用自然语言或已有图表源生成内嵌 SVG 的 HTML，并可沿用网站的颜色与字体。

主要功能：

  • 按图的表达目的选择架构图、时序图等模板，输出可直接打开的 HTML。
  • 可重绘 Mermaid、draw.io 等来源，或提取指定站点的配色；按用途导出 SVG 或 PNG。

适用场景：

  • 把设计草图做成适合发布在博客或演示文稿里的架构图。
  • 在多张培训配图中统一强调色、字体与图例样式。

使用前提：需要支持 Agent Skills 的宿主；固定版本 README 的 PNG 导出依赖 Playwright 与 Chromium，SVG 离线使用需留意字体选项。

权限与限制：模型参与摆放，同一输入未必得到相同布局；生成物不保留为可拖拽的源文件。需要随代码频繁审阅差异时，不宜替代文本图表源。

许可证提示：GitHub 仓库元数据标记 MIT；若图中引入外部字体、图标或素材，须另查其授权。

来源：README（本期参考版本）

6. zhouxiaoka/autoclip

核心定位：将长视频或直播回放拆成短片的桌面和命令行工具，把片段选择、说话人跟踪、字幕和封面生成接在一次处理里。

主要功能：

  • 从本地视频、链接或直播回放挑选片段，生成带字幕的不同平台版式。
  • 切割和渲染在本机进行；文字分析与转写可选本地模型，也可接云服务。

适用场景：

  • 从已获授权的播客或访谈中剪出竖屏片段，再人工复查字幕和上下文。
  • 为同一课程片段准备横版和竖版导出，保留原始录像。

使用前提：桌面包面向 Apple Silicon 与指定的 Windows x64 版本；CLI/MCP 需 Python 和 FFmpeg，本地转写和分析另需对应模型。

权限与限制：云分析、视觉模型和云转写分别可能接收字幕文本、抽取帧和音频；云服务可能计费，直接发布还涉及平台账号授权。

许可证提示：README 标明工具使用 MIT；它不授予视频素材、人物肖像或音乐的使用权。

来源：README（本期参考版本）

7. mvanhorn/last30days-skill

核心定位：围绕一个主题并行查找近期跨平台讨论，按相关性、时间和互动筛选，将同一事件合并成带来源的简报。

主要功能：

  • 从 Reddit、Hacker News、视频转录等入口取样，具体可用来源取决于所选后端。
  • 支持 Markdown 快照和结构化输出；同一故事的跨平台提及可以合并，而不是逐条重复罗列。

适用场景：

  • 比较工具时先找到近期常见问题，再回原帖与官方文档逐条核实。
  • 会前整理一个技术主题最近的社区讨论与待确认问题。

使用前提：README 列出 Python 3.12+，部分来源还需要 yt-dlp 等工具；平台覆盖受登录、API 凭据、开通范围和计费影响。

权限与限制：互动分不是事实可靠性；各来源不一定都覆盖整整 30 天。默认重排可能使用环境中的凭据并把主题和入选片段送给外部模型。

许可证提示：固定版本 README 写明 MIT；引用社区帖子、转录或平台数据仍应保留归因并尊重各来源规则。

来源：README（本期参考版本）

8. HKUDS/CLI-Anything

核心定位：为已有应用生成可由代理调用的命令行包装层，也提供目录，让团队先查找现成接口再决定是否生成。

主要功能：

  • 生成命令组、帮助说明和配套的技能文档，给代理提供稳定的操作入口。
  • 项目描述的包装层调用实际应用完成处理，并配套单元、端到端和命令行进程测试。

适用场景：

  • 为团队已有的制图或媒体应用封装可在测试环境重复执行的操作。
  • 在多个工作流共用一个内部工具时，先固定输入和输出，再逐项验证命令。

使用前提：生成路径需 Python 3.10+、支持的编码代理与可访问的目标程序或源码；使用生成物时仍可能要安装底层应用。

权限与限制：不能仅凭接口生成成功就认定覆盖了应用能力；应先审查目录来源、底层命令和写入权限，再用测试数据验证。

许可证提示：固定版本 README 标明 Apache-2.0；被包装的目标程序及从目录获取的第三方工具另查许可。

来源：README（本期参考版本）

9. jingyaogong/minimind

核心定位：一套从分词和模型结构入手练习小语言模型训练的代码与教程，可分阶段观察预训练、指令微调和其他扩展步骤。

主要功能：

  • 提供稠密与 MoE 结构代码，以及预训练、指令微调和中间权重等教学材料。
  • 可在同一套代码上追加 LoRA，比较低秩分支与全参数微调所需的资源和产生的权重。

适用场景：

  • 在课程实验中跑通从数据准备到对话模型训练的最小链路。
  • 用小模型比较全量微调和 LoRA 的训练过程，而非比较生产模型性能。

使用前提：需 Python、适配的 PyTorch 后端、训练数据和存放权重的空间；使用 CUDA 前应确认驱动、显存和设备识别。

权限与限制：README 的时间和费用说明基于特定硬件、数据与阶段，不能当完整流程的普遍承诺；CPU、MPS 与 CUDA 的速度和兼容性可能不同。

许可证提示：项目 README 声明 Apache-2.0；引用或再分发时仍应检查各外部数据集及权重的单独条款。

来源：README（本期参考版本）

10. mjmirza/app-store-compliance

核心定位：面向移动应用提交前的项目扫描脚本和人工清单，帮助团队把常见拒审点整理成可复核的检查项。

主要功能：

  • 在包含 Xcode 或 Android 项目的目录查找规则风险，并给出触发位置。
  • 配套清单还覆盖扫描无法确认的事项，如演示账号、线上后端和实际隐私声明。

适用场景：

  • 在提交移动应用前，把隐私声明和权限提示分配给开发与发布负责人逐项复核。
  • 收到拒审结果后，用清单定位相关项目区域，再到对应商店官方页面核对。

使用前提：固定版本 README 的单次扫描依赖 Git 和 Bash 及可读取的项目目录；核对账号和商店资料仍需负责人参与。

权限与限制：静态扫描不覆盖运行时、账号或店面全部信息；没有查到高风险不等于获准上架，实际要求以平台的有效官方规则为准。

许可证提示：GitHub 元数据未确认标准许可；该版本 README 标明 OpenRoots Agent License 2.3，使用和分发前应核对原条款，不当作 MIT。

来源：README（本期参考版本）
