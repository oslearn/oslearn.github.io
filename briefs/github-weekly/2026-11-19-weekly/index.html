项目介绍

GoogleChrome/modern-web-guidance-src

Modern Web Guidance把浏览器能力、兼容性资料与现代Web写法整理为编码代理可检索的指南。这个仓库负责指南的编写、校准和评估，适合让代理在改前端代码前查明原生能力与必要回退，而不是不断补旧式脚本。

主要功能

  • 按任务检索指南，并扫描代码中的旧式实现
  • 结合浏览器支持情况选择渐进增强与轻量回退
  • 对实验性或尚不稳定的特性设置采用门槛

应用场景

  • 前端代码现代化与兼容性评审
  • 给编码代理补充具体Web平台知识

前提与限制：需要支持本地命令的编码代理和相应Node工具链。文档说明默认采集检索等遥测，可退出；源码与指南采用不同许可。这里只读了功能、采用门槛、隐私和许可段落，未验证评估成绩。

dream-num/univer

Univer提供嵌入产品的办公编辑基础，让网页应用处理表格和富文本文档，并通过同一套内容模型与命令接口连接业务系统或既有代理。本仓库是其中的开源Web核心，不应把整套商业Office SDK展示的能力都算进默认安装。

主要功能

  • 表格编辑、公式计算、筛选、排序与数据校验
  • 富文本编辑及插件化命令、撤销重做
  • 通过Facade接口和内容快照连接业务应用或无界面处理

应用场景

  • 在业务系统嵌入表格或文档编辑器
  • 将代理操作接入可审阅的办公内容工作流

前提与限制：需前端集成和权限设计。协作后端、文件交换及部分AI扩展单独分发和授权，试用可能有限制；运行时需注意Intl.Segmenter等兼容条件。本次只读核心范围、能力、许可与运行条件，未测试商业组件。

已读 README

meta/astryx

Astryx是一套React设计系统，把组件、主题、模板、文档和CLI放在一起，供开发者与编码代理用同一套接口搭建界面。它强调开放组件内部结构、通过CSS变量改品牌主题，以及在需要时把组件源码移入项目自行维护。

主要功能

  • 提供可组合组件、主题和深浅色样式
  • 以CSS变量及现有样式方式调整界面外观
  • 通过CLI与文档为人和代理提供一致的组件用法

应用场景

  • 统一产品界面与品牌主题
  • 让编码代理按已有设计系统生成页面

前提与限制：文档标为Beta，需要React 19或更新版本及相应依赖。源码自定义后需承担维护工作；组件可访问性属于项目方说明，本次未独立验证。已读概览与安装说明，未逐个审阅组件实现。

已读 README

alibaba/open-code-review

Open Code Review面向代码审查：根据Git差异或指定文件确定审阅范围，组织相关上下文和规则，再输出定位到代码行的结构化意见。除由工具自行调用模型外，它还提供宿主代理完成审阅的模式，可复用环境中的模型与认证。

主要功能

  • 审阅工作区、分支、提交差异或完整文件
  • 组织关联文件与适用规则，生成结构化审查意见
  • 在独立模型模式与宿主代理审阅模式之间选择

应用场景

  • 提交前检查和变更评审
  • 对陌生代码库进行定向扫描

前提与限制：需Git及ocr工具。原生模式另需模型配置，宿主模式也受环境权限与用量限制；代码可能进入模型上下文，使用前应核对外发范围。只读功能、设计、前提和模式说明，未验证其基准或缺陷检出率。

已读 README

we-promise/sure

Sure是Maybe Finance的社区维护分支，提供可自托管的个人财务管理应用。读者可把它理解为集中管理财务资料的应用入口，而不是自动替人作投资决策的系统；仓库介绍了浏览器、客户端、API和代理访问方式。

主要功能

  • 以Docker自托管个人财务应用
  • 通过浏览器、客户端或API访问应用
  • 提供不启用AI和接入AI服务的不同部署配置

应用场景

  • 在自己管理的环境集中处理财务资料
  • 扩展个人财务应用与数据访问入口

前提与限制：财务资料敏感，需自行保护访问权限、数据库和备份；AI配置可能带来数据外发和费用。项目采用AGPLv3，服务部署成本另计；文档承认存在性能问题。本次读了README，未审计具体银行同步或安全实现。

已读 README

backnotprop/plannotator

Plannotator为编码代理提供本地浏览器审阅界面：用户能批注计划、文档、页面和代码差异，再把反馈送回发起任务的代理。Inbox把多个会话的待决问题与文件集中起来，适合需要人保留关键判断的协作流程。

主要功能

  • 批注文档、计划、HTML与代码差异并回传反馈
  • 将较大变更组织为便于阅读的审阅章节
  • 以Inbox集中处理多个代理会话留下的问题和文件

应用场景

  • 在代理继续编码前审阅重要方案
  • 管理多会话反馈与较大变更评审

前提与限制：需对应插件、钩子或MCP连接，平台支持有差异；安装及可选AI功能会涉及外部服务。分享完整链接的持有者可读内容，大分享可能上传，因此不宜直接分享敏感代码。本次仅审阅README功能、安装和分享说明。

已读 README

tradermonty/claude-trading-skills

Claude Trading Skills把市场回顾、风险检查、计划、记录和复盘组织为技能与工作流，侧重帮助使用者形成可追踪的研究过程。作者明确说明它不是信号服务或经纪商执行平台，也不是把买卖决策交给AI的自动交易系统。

主要功能

  • 按工作流组织市场回顾和组合研究
  • 把风险检查、计划与交易记录串成流程
  • 提供示例产物及无需付费数据API的基础路径

应用场景

  • 整理教育性市场研究和复盘资料
  • 对研究流程的输入、判断关口与记录方式进行检查

前提与限制：仅作教育、研究与流程整理，不是投资建议或收益保证；某些流程需Alpaca或FMP等数据接口，可能有费用并涉及账户资料。工具输出不能替代独立判断。本次只读定位、免责声明、流程表和起步说明，未验证策略或回测。

已读 README

ag-ui-protocol/ag-ui

AG-UI用事件协议连接代理与面向用户的应用，把流式文本、工具调用、共享状态和需要用户参与的过程放到一致的数据通道中。它用于减少不同代理框架和前端之间的重复接线，不是独立的大模型服务。

主要功能

  • 以类型化事件传输代理执行过程与流式输出
  • 支持应用与代理之间的双向状态交换
  • 提供SDK及应用脚手架作为接入入口

应用场景

  • 给已有代理增加Web或其他客户端界面
  • 统一不同框架的工具调用与交互状态展示

前提与限制：仍需应用端、代理端及各自认证和权限设计；示例模板可能调用外部模型服务并产生费用，协议本身不等于提供模型。本次读了协议定位和快速起步段，未核验全部集成及兼容性宣称。

已读 README

ChromeDevTools/chrome-devtools-mcp

Chrome DevTools MCP把浏览器开发工具的检查能力提供给编码代理，支持观察页面、网络请求、控制台消息和性能轨迹，并通过自动化操作复现交互问题。适合把代理的推测与真实浏览器现象联系起来。

主要功能

  • 读取网络与控制台信息并辅助定位页面异常
  • 记录性能轨迹并整理诊断线索
  • 自动化浏览器操作、截图和交互检查

应用场景

  • 复现前端故障与排查性能问题
  • 让代理检查网页实际交互而不只阅读代码

前提与限制：需Node运行时、Chrome及MCP或CLI接入。它可暴露浏览器内容与登录态，应使用受控测试环境；默认遥测及性能接口可能外发信息，文档提供关闭选项。本次读了功能、隐私和运行条件，未连接真实浏览器测试。

已读 README

kajisho5/ffmpeg-skill

ffmpeg-skill把本地音视频编辑整理成代理可调用的工具与流程：先检查素材，再剪辑、拼接、调整画面或音频，最后验证导出文件。它支持Skill与MCP入口，适合不希望上传素材的批处理任务，但文件检查不等于主观质量评审。

主要功能

  • 剪切、拼接、比例调整与音频响度处理
  • 组织字幕、叠加元素及批量编辑任务
  • 探测环境能力并检查输出媒体参数

应用场景

  • 在本地批量整理音视频素材
  • 让代理按可复核流程处理短视频交付

前提与限制：需本机FFmpeg、ffprobe和Python，具体能力取决于构建组件及额外工具。涉及写入和覆盖媒体文件，需隔离原件并检查结果；演示和验证能力属于项目方说明。本次读了概述和主要工具清单，未核验每个工具或视觉质量。
